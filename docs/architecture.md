# Architecture

Vanilla HTML/CSS/JavaScript SPA. No build step, no framework, no backend. Demo state persists to localStorage.

## Screens (`index.html`)

Every screen is a `.screen` div; only the `.active` one is displayed. Screens toggle via `showScreen()`.

| Group | Screens |
|---|---|
| Auth | `screen-welcome`, `screen-login`, `screen-register` |
| Resident | `screen-resident-home`, `-wallet`, `-qr`, `-rewards`, `-profile`, `-notifications` |
| Collector | `screen-collector-home`, `-scan`, `-records`, `-notifications`, `-profile` |
| Admin | `screen-admin-home`, `-manage`, `-reports`, `-notifications`, `-profile` |

Overlays: bottom navs (`nav-resident`, `nav-collector`, `nav-admin`) and modal bottom sheets (`.modal-overlay` / `.modal-content`). Modal close animates out via `.closing` (slide down + fade); Escape routes through `closeModal()`.

## Navigation & Motion

- `showScreen(screenId, direction)` — tab taps pass a direction and slide full-width; auth/welcome routes fade. Direction comes from `TAB_ORDER` (notifications = rightmost).
- Auth transitions: `handoffTo(targetId, opts)` is the single Welcome → Login → Create Account transition. It measures the destination logo slot on a hidden `.handoff-measure` layout, clones the mark into a body-level `.handoff-mark` and flies it with WAAPI (620ms, `cubic-bezier(0.23,1,0.32,1)`) while the two screens cross-dissolve (`.handoff-out` / `.handoff-in`, 480ms); the clone dissolves onto the real artwork on landing. `goToLogin()` (welcome → login), `goToRegister()` (login → create account) and `backToLogin()` (register → login) all route through it. `doLogin()` adds `.login-leaving` to the login wrap, then role-routes through `route()` and focuses the home greeting. `showScreen` strips the transient handoff classes and resets `loginLeaving` on return to login; `prefers-reduced-motion` routes instantly with no flight. Double-taps are guarded by the `handoffBusy` / `loginLeaving` flags.
- Shell headings: only Home renders the brand masthead. Resident root tabs EcoWallet, My QR, Rewards, and Profile use a single contextual `.page-title-block h1`; root tabs have no back arrow. Nested detail pages keep their compact back header.
- `glideTo(fromEl, toEl, direction, staged)` is the single slide engine. CSS transitions drive the glide so mid-slide taps retarget smoothly. `glideFinish()` finalizes; `showScreen` flushes any pending glide first.
- Swipe pager: `initSwipeNavigation()` binds touch handlers on every `.screen`. Horizontal lock at ~10px, finger-tracking 1:1, commit at 30% width or a fast flick (>40px & velocity), otherwise spring back. Horizontal-scroll children (chips, rails) are excluded at touchstart. `swipeNeighbor()` never routes into or out of `scan`: the collection wizard is a focused task, entered from the dashboard action and left through Back/Cancel.
- Entrance choreography (welcome + login sequences, register form cascade, one-shot post-login home entrance) lives in CSS keyed on `.active` / `.entrance-dramatic`. The welcome screen runs a 5-stage ~1.8s sequence — scene fade, mark scale-in with a clipped logo reveal, environment draw-in (contours draw, canopy/ribbons fade), typography (masked line rises + lime underline wash), CTA spring — and it never blocks interaction. Login staggers the brand, title, inputs, and demo panel; Register staggers header, intro, and icon-prefixed fields. The `.entrance-dramatic` class is stripped after ~1.5s so high-frequency tabs never replay drama.
- Welcome environment: the scene is a single inline SVG (`.wlc-art`) plus CSS layers — topographic contours (`.wlc-contour`), canopy silhouettes (`.wlc-canopy`), gradient ribbons (`.wlc-ribbons`), a recycling-loop motif (`.wlc-motif`), drifting light pools (`.wlc-glow-a/b`), a sweeping light pass (`.wlc-light`), luminous motes (`.wlc-mote-*`) and a tiling grain texture (`assets/grain.png`). All ambient motion is transform/opacity only. `initWelcomeInteractions()` (called from `DOMContentLoaded`) adds the logo tap ripple (`.welcome-visual.is-rippling`) and a pointer parallax on the scene via the `--wlc-px` / `--wlc-py` custom properties, reset on `pointerleave` / `pointercancel`.
- Authentication interactions: `togglePassword()` swaps between `.eye-open` and `.eye-closed` outline SVGs; `toggleRegisterPassword()` toggles password masking; `toggleDemoPanel()` drives `aria-expanded` and chevron rotation for the prototype account picker; `fillDemo()` autofills credentials with active card highlighting (`.selected-demo`).
- Reduced motion: JS glide finalizes instantly; CSS entrances collapse to a 0.2s fade.

## Rendering

- `updateResidentUI()` (full render after login/action) and `updateResidentHomeUI()` (home refresh) update metrics, greeting, badges, and re-render lists.
- `refreshTab(role, tab)` — one shared per-tab refresh for tap navigation and swipe commits (prevents drift between the two paths). Content refresh runs **before** the glide starts so no re-render frame lands mid-motion.
- Collector workflow: `showCollectorTab('scan')` and dashboard `startNewCollection()` open the Scanner root with bottom nav visible. The Scanner root (`#scan-root-surface`) owns the app's only scanning viewport; the wizard chrome lives in the same screen but owns no viewport. `selectedResident` is the single verified-resident state — `setVerifiedResident()` / `clearVerifiedResident()` write it, `renderVerifiedResident()` paints it into both surfaces, and `scanSession` owns the viewport lifecycle (`startScanSession()` / `stopScanSession()`) so it starts at most once, pauses on verification, and never resumes while the wizard owns the screen. Demo selection reads the resident account and verifies it; `renderScanSurface()` replaces the viewport with the verified card and the two follow-up actions (Scan Different Resident, Continue Collection). Continue Collection calls `startDepositWizard()`, requires a resident and enters material selection at step 2 without resetting the draft. Step 1 is completed; Back from step 2 shows the verified resident summary (`#wiz-resident-card`), never a second scanner. Changing residents inside the wizard uses the discard guard; on the Scanner tab it clears the resident and restarts scanning. Success resets the finished draft and offers Records or the Scanner root. There is no live camera/decoder or production QR verification service in this browser-only demo.
- `confirmDeposit()` keeps the original data mutations (record, resident points/transactions, collector/admin totals, notifications, audit log) but sets `depositInFlight` before writing, fills the compact success sheet, adds `body.deposit-success-open` (hides the wizard behind the sheet), and resets the draft. The success sheet is a decision point: outside click and Escape cannot dismiss it; `finishDepositSuccess()` goes to Records, `startAnotherCollection()` restarts at step 1.
- Collector dashboard (`col-*`): `updateCollectorHomeUI()` binds officer identity/initials (`collector-officer-name`, `-avatar`, `-barangay`, `-id`), the daily-performance metrics (`collector-kg-today`, `collector-tx-count`, `collector-pts-awarded`, `collector-types-count`), and `renderCollectorRecentDeposits()` — the latest three records built with DOM APIs (`textContent`/`replaceChildren`) and 3-line `.col-row` rows (name, material · weight, full date; right column points + status). Rates stay live from `AppState.wasteMaterials`; no derived statistics are invented.
- Collector Records: `currentRecordFilter` remains the search/material/date source of truth, including selected-control ARIA. `renderCollectorRecords()` builds keyboard-accessible receipt rows with DOM APIs and distinct empty/search/date/unavailable messages. `collectorLocalDateKey()` uses local calendar dates for new deposits and filtering; This Week means Monday–Sunday, with an exclusive next-Monday bound. Historical date-only values retain their recorded day. Material inventory is an explicitly all-time summary, refreshed with Records.
- Collector Profile: `renderCollectorProfileScreen()` uses the shared `.profile-screen` / `pf-*` system. The identity shows authorization, barangay, ID, email, and registration date; matching uses collector ID/email, never an unrelated first-collector fallback. Performance uses the collector's stored waste/points totals (own records as fallback), explicitly verified/unflagged deposits on file, and enabled program material types when available. The information card includes contact and account status. Notifications, coming-soon Help & Support, and Logout retain their handlers; no collector edit/password action is added.
- Admin Profile: `renderAdminProfileScreen()` uses the same identity, two-column statistics, information, settings, and logout components. Program overview reads `AppState.admin` waste, residents, points, and vouchers; account information comes from the admin user. Notifications and coming-soon Help & Support retain their handlers.
- `renderHomeRecentTransactions()` / `renderHomeActivities()` build Home lists from `AppState`. `renderTransactions(filter)` builds the wallet feed with month grouping.
- `renderRewards()` builds the single-column reward-ticket catalog and balance strip. `splitRewardOffer()` hoists `₱50` / `10%` out of the live name for display only; `rewardInitials()` supplies deterministic merchant monograms. The disabled `Need N` stub is non-blocking: tapping the card area still opens the detail sheet.
- `renderVouchers(tab)` builds voucher rows and calls `updateVoucherCounts()` for `#rewards-voucher-count`, `#vouchers-total`, and the three tab counters. `switchVoucherTab()` drives `#voucher-tab-bar` and `aria-pressed`.
- `confirmRedemption()` sets `redemptionInFlight` before mutating state, so a queued double tap cannot redeem twice; `confirmRedemptionOpen()` resets it for the next confirmation.
- Category rail: `#rw-chips` is a self-contained horizontal scroller (no wrap/shrink, hidden scrollbar, no edge-fade overlays — a clipped chip is the scroll cue). `updateRewardsChipFade()` is retained as a dataset-only no-op for compatibility; `initRewardsChipScroll()` ensures the rail starts at `scrollLeft 0` and binds scroll/resize/ResizeObserver once.
- `createActivityRow(tx)` is shared by Home and EcoWallet: button rows with material-specific outline icons, metadata, amount, and text status. Dynamic strings go through `textContent` (XSS-safe).
- `renderQRScreen()` binds name/ID/pattern and the QR `aria-label`.
- Resident Profile (`#screen-resident-profile`, `pf-*` classes): `renderProfileScreen()` binds identity (`profile-name`, `profile-email`, `profile-barangay`, `profile-member-since`, `profile-avatar`), the impact ledger (`profile-total-kg`, `profile-total-deposits`, `profile-lifetime-pts`, `profile-community-events` = approved `AppState.activities` count), and personal details (`profile-id`, `profile-display-phone`, `profile-email-detail`, `profile-barangay-detail`, `profile-municipality`). `setEditProfilePanel(open)` owns the inline edit disclosure (`hidden`, `aria-hidden`, `aria-expanded` on both Edit buttons, scroll-into-view); `saveProfileEdit()` persists name/contact only — email is `readonly` with an explanatory note. All three role profiles share its visual foundation; editing remains resident-only.
- Admin Dashboard (`#screen-admin-home`): `updateAdminUI()` drives the single branded admin masthead (`admin-header-light`), executive identity (`admin-home-avatar`, `admin-home-office`), KPI card (total waste diverted, registered residents, points distributed, vouchers claimed), and coverage summary accordion (`toggleBarangaySummary()`). Visual analytics include 7-day proportional waste trends with zero-value visibility (`renderAdminTrends()`), responsive 3-column Material Share (`renderAdminMaterialShare()`), and rankings distinguishing enrolled vs active deposit barangays (`renderAdminBarangayRankings()`).
- Admin Manage (`#screen-admin-manage`): Contextual `.page-title-block` with 4 pill navigation tabs (`showManageTab`: categories, rewards, collectors, activities). Features responsive 3-tier collector cards (`.collector-row`), full-width `.manage-card-row` items for initiatives/proposals, independent modal scrolling for Collector Details (`#modal-collector-details`), and safe proposal workflows in `openEventProposalReview()` (total budget preview, distinct revision request vs approval, duplicate-action lock via `proposalActionInFlight`).
- Admin Audits & Reports (`#screen-admin-reports`): `getAdminReportFilters()` reads the controls; `getFilteredAdminRecords()` combines search/material/collector/date with AND logic. `filterAdminReports()` supplies the same result to Flagged Activity and Verified Transactions, including tab/admin refreshes. Dates use local Today, Monday–Sunday, or calendar-month bounds; date-only records retain their day. Section counts and empty states reflect visible records; the header and CSV retain all deposits. Clear filters appears in `#reports-filter-actions` beneath the dropdowns only when active. Review handlers are preserved. System Audit Log remains independent and retains its eight-entry display limit; `formatAuditTimestamp()` restores the UTC convention of `nowStr()` before local date/time formatting. `parseAuditDetail()` splits each action's detail into logical display lines (primary first) and `appendAuditTokens()` marks IDs/EcoPoints with styled spans; IDs never truncate and amounts keep their units. Existing grouped cards and safe-area bottom clearance are retained.
- Toast Notification Architecture: Single fixed `#app-toast` positioned at the top (`top: calc(14px + env(safe-area-inset-top, 0px))`), ensuring transient alerts never overlap transaction lists, bottom controls, or navigation tabs. Supports tap-to-dismiss and automatic dismissal during screen navigation in `showScreen()`.

## Count-up gating

`setNumberAnimated()` animates only while `countUpArmed` is true. `doLogin()` arms it, renders the role home (count-up plays once with the points-card pop), then disarms. All other renders set text instantly.

## QR

`generateQRPattern(seed)` builds a deterministic 21×21 pattern (demo pattern, not an ISO QR). `renderQRGrid()` renders it as CSS cells. `createResidentQrBlob()` renders the same modules to a PNG canvas (quiet zone included) for `downloadResidentQr()` / `shareResidentQr()`. `copyResidentId()` uses the live user ID with clipboard API + textarea fallback.

## Graphify navigation

`graphify-out/graph.json` (generated, gitignored) indexes symbols, call edges, and doc concepts. Use it as a navigation aid — not a source of truth:

- `graphify query "<question>" --budget 800` — scoped context for "how does X work"
- `graphify path "A" "B"` — trace relationships between symbols
- `graphify explain "X"` — god nodes / neighbors
- `graphify update .` — incremental rebuild after code edits (AST-only, no LLM cost)

Prefer grep for exact symbol text; prefer the graph for relationships and call chains. If the graph is missing, work directly from the files. Rebuild only when navigation questions arise — not on every edit.

## QA harness

`tests/ui-checks.html` iframes the app at a chosen width; `runUiChecks()` in `tests/ui-checks.js` asserts no horizontal overflow and ≥44px targets at 320/375/390/430, navigation + selected state, quick actions, wallet/rewards filters, dialog open/close, reduced motion, long/empty states, safe text rendering, and factual metric calculations. Fixtures mutate in-memory state only and are restored.
